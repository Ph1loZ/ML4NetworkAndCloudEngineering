⚙️ ตัวแปร (Hyperparameters)

max_depth 3
ความลึกสูงสุดของต้นไม้: "จำนวนคำถามต่อเนื่องที่ AI ควรถาม"
📌 หากค่าน้อยไป (1-2) AI จะแยกข้อมูลไม่ละเอียด (Underfitting)
📌 หากค่ามากไป ต้นไม้จะจำรายละเอียดหยุมหยิมมากเกินไป (Overfitting)
min_samples_split 20
ขั้นต่ำที่จะแบ่งต่อ: "จำนวนข้อมูลในกลุ่ม ต้องมีอย่างน้อยกี่ตัว ถึงจะยอมตั้งคำถามแบ่งกลุ่มต่อ"
📌 ช่วยหยุดต้นไม้ไม่ให้แตกกิ่งก้านสาขาในกลุ่มข้อมูลที่เล็กเกินไปแล้ว
min_samples_leaf 5
ขั้นต่ำของผลลัพธ์: "คำตอบสุดท้าย (Leaf) ต้องมีข้อมูลอ้างอิงอย่างน้อยกี่ตัว"
📌 ป้องกันไม่ให้ AI สร้างกฎขึ้นมาเพื่อตัดสินข้อมูลแค่ 1-2 ตัว (กัน Noise)

💡 วิธีใช้งานสำหรับนักศึกษา (What they will learn) เมื่อนักศึกษาเปิดไฟล์นี้ จะพบกับแถบเลื่อน 3 ตัว ซึ่งอธิบายพฤติกรรมหลักดังนี้: ลองเลื่อน max_depth (ความลึก): หากตั้งเป็น 1 ต้นไม้จะถามแค่ข้อเดียวแล้วสรุปผลเลย (เห็น Node สั้นมาก) หากตั้งเป็น 5 ต้นไม้จะยาวลงมาเรื่อยๆ (เสี่ยง Overfitting มากขึ้นถ้าข้อมูลมีน้อย) ลองเลื่อน min_samples_split: หากดันค่าไปสูงๆ (เช่น 40) จะสังเกตเห็นว่า แม้จะตั้ง max_depth ไว้ลึก 5 ชั้น แต่ต้นไม้จะหยุดโตเร็วมาก (กล่องสีเหลือง) เพราะกลุ่มข้อมูลถูกหั่นจนเหลือไม่ถึง 40 ตัว อัลกอริทึมจึงปฏิเสธการแบ่งต่อ ลองเลื่อน min_samples_leaf: หากตั้งไว้สูง (เช่น 20) อัลกอริทึมจะประเมินล่วงหน้าว่า "ถ้าหั่นครึ่งแล้วได้กลุ่มย่อยน้อยกว่า 20 ตัว จะไม่หั่นเด็ดขาด" (กล่องสีเขียว) ทำให้ปลายทางแต่ละ Node มีความน่าเชื่อถือสูงขึ้น ป้องกันการแยกกฎให้ข้อมูลส่วนน้อย (Noise) ระบบเขียนด้วย Logic การหั่นข้อมูล (split) แบบ Recursive คล้ายกับที่ Scikit-learn ทำงานจริงหลังบ้าน ทำให้นักศึกษาเห็นผลกระทบของ Parameter ที่สัมพันธ์กันแบบ จะเห็นแอนิเมชันการทะยอยโหวต (เขียว หรือ แดง) ของแต่ละต้น หากต้นไม้เยอะ ผลรวมของการโหวต (แถบสีด้านบน) จะนิ่งและน่าเชื่อถือมากขึ้น max_depth (ความลึกของแต่ละต้น): เปรียบเสมือน "ระดับความซับซ้อน" ที่กรรมการแต่ละคนจำแนกข้อมูลได้ เมื่อนักศึกษาปรับค่านี้ ไอคอนต้นไม้จะเปลี่ยนจากต้นอ่อน (🌱) เป็นต้นไม้ธรรมดา (🌲) และต้นไม้ใหญ่ (🌳) เพื่อแสดงถึงความซับซ้อนของ Model max_features (การสุ่มเปอร์เซ็นต์เบาะแส): อธิบายเรื่อง Diversity (ความหลากหลาย) ซึ่งเป็นหัวใจหลักของ Random Forest หากตั้งไว้ที่ 100% กรรมการทุกคนจะเห็นข้อมูลเหมือนกันหมด ทำให้โหวตไปในทิศทางเดียวกัน แต่ถ้าลด % ลง กรรมการแต่ละต้นจะสุ่มดูข้อมูลแค่บางส่วน (เช่น ดูแค่ Port หรือดูแค่ IP) ทำให้เกิดความแตกต่างทางความคิด ลดปัญหา Overfitting ได้ดีเยี่ยม คุณสามารถนำไฟล์นี้ไปให้นักศึกษาเปิดเล่นบน Browser หรือนำไปโฮสต์ไว้บน GitHub Pages แบบเดียวกับไฟล์ Decision Tree ก่อนหน้านี้ได้เลยครับ! ช่วยทำ html page 1 หน้า เพื่อแสดงการทำงานของ Random Forest โดยทำเป็นเกมหรือกิจกรรม แล้ว virtualize ให้นักศึกษาลองเล่นด้ว Random Forest เพื่อให้นักศึกษาที่ไม่มีความรู้พื้นฐานเข้าใจ Random Forest มากขึ้น ขออันนี้ก่อนครับ Machine Learning for Network and Cloud Engineering Custom Gem จัดให้ตามคำขอครับ! สำหรับอันนี้จะเป็น ส่วนของเกม/กิจกรรม (Game Activity) เพื่อให้นักศึกษาเข้าใจคอนเซ็ปต์การทำงานของ Random Forest แบบไม่ต้องแตะ Parameter เลยครับ ไฟล์ของคุณพร้อมแล้วครับ HTML icon RandomForest_Game HTML 💡 แนะนำวิธีกระตุ้นนักศึกษาจากเกมนี้ (เกมจับผิดแฮกเกอร์): เกมนี้จำลองหลักการสำคัญที่สุดของ Random Forest คือ "Feature Bagging" (การสุ่มเลือกเบาะแส) โดยให้นักศึกษาลองสวมบทบาทเป็นคนกำหนดพฤติกรรม Network Traffic 3 อย่าง (ประเทศ, ความเร็ว, การเดารหัส) ให้นักศึกษาลองเลือกข้อมูลที่ขัดแย้งกัน: เช่น มาจาก ไทย (ปกติ) + ความเร็วช้า (ปกติ) + แต่ เดารหัสผิด 50 ครั้ง (แฮกเกอร์) กดปุ่มส่งให้ AI ตรวจสอบ: นักศึกษาจะเห็นว่า "กรรมการต้นที่ 1" (ที่เห็นแค่ ประเทศและความเร็ว แต่ไม่รู้เรื่องรหัสผ่าน) จะโหวตว่า "เป็นผู้ใช้ปกติ" ในขณะที่ "กรรมการต้นที่ 2 และ 3" (ที่เห็นข้อมูลการเดารหัส) จะโหวตว่า "เป็นแฮกเกอร์" ผลลัพธ์ (Majority Vote): ถึงแม้จะมีกรรมการโหวตพลาดไป 1 ต้น แต่เสียงส่วนใหญ่ก็ยังชนะและโหวตว่าเป็นแฮกเกอร์ได้ถูกต้อง นี่คือวิธีอธิบายให้นักศึกษาเห็นภาพว่า ทำไม Random Forest ถึงเก่งและมีความเสถียรมากกว่า Decision Tree ต้นเดียว (Wisdom of the Crowd) ครับ! คุณสามารถนำไฟล์ HTML นี้ไปเปิดใน Browser เล่นบนโปรเจคเตอร์ในห้องเรียนได้เลยครับ Gemini is AI and can make mistakes.
